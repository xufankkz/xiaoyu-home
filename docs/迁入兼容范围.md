# 迁入兼容范围与恢复边界

先保留并核验源软件备份，在“迁入与备份”选择文件预览，只显示结构、计数和差异；确认后才写入本实例。无需把原文、Key或包密码粘贴到云端聊天。

| 来源 | 支持内容 | 边界 |
| --- | --- | --- |
| 小鱼之家0.2.0-beta.1 `.fish` | 本版本核心库有主键的已适配表、人格/角色资料、受支持的日记/记忆/state/学习文档、本地聊天历史、称呼及空白实例的外观 | AES-GCM+Scrypt加密，密码至少8字符；不含凭据、外部权重或完整媒体库；128MiB上限 |
| AstrBot livingmemory数据库 | documents表中的doc_id/text/metadata；原文、来源ID、会话、原时间和删除标志 | 仅明确的三列结构，不声称适配所有插件或AstrBot整机备份；WAL数据库请先在源端做一致性备份 |
| DSH原生完整JSONL / JSONL.Zst | 官方版本化codec支持的完整会话中的用户/助手文本；原事件、会话、时间、ID、替换/删除关系保存在来源元数据 | 需要DSH组件；未知/不完整/依赖子会话证据的格式拒绝；不继续旧任务，不把工具执行状态迁成新动作，附件仍需原文件 |
| DSH / AstrBot约定JSON导出 | sessions/messages-v1文本对话 | 不是对任意原始目录的识别。示例结构如下，保留原始ID，不自行猜测缺失字段 |

```json
{"sessions":[{"id":"原会话ID","messages":[{"id":"原消息ID","role":"user","content":"原文","created_at":"原时间","deleted":false}]}],"profile":{"name":"角色名","owner_address":"称呼","description":"简介"},"persona":"原人设"}
```

增量规则：同主键的既有行保留；冲突不覆盖、不复活已删除项。缺失文档才补入。新空白实例可采用原人设/外观；已有角色不覆盖。联系人称呼不等于QQ授权，导入不扩大白名单，历史消息不会重新发送。跨对话的去重/送达账本及第三方插件运行状态尚不包含在当前迁移契约中；原软件须留档，首次外发前核对权限和单一回复链路，不能声称这些状态已完整搬迁。

迁入前使用SQLite备份API建立并核验快照，保留配置快照、源文件SHA-256与journal。核心DB事务与文件补齐不是全局原子事务；journal记录prepared/database_committed/completed。中断时保留源文件和本实例，重新预览以补齐缺失项；不要覆盖整库或自动恢复旧快照，以免丢掉迁入后新增资料。自动一键回滚向导尚未提供，备份可供维护者按journal核对后恢复。完成迁入会重载本实例核心以更新缓存，不影响其他安装。

导出文件包含私人原文，请保存密码并妥善保管。没有中央密码找回；换Windows账号/电脑后DPAPI凭据需重填。完整旧软件人设/语音映射/插件配置迁移仍需对应适配器，不能用提示词代替尚不存在的工具。
